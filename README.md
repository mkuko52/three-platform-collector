# 三平台单文件采集

**首次使用请看：[使用说明.md](使用说明.md)**（安装、登录、启动、结果查看、断点续采及常见问题）。

三个采集脚本统一存放在 `collectors/`：`douyin.py`、`kuaishou.py`、`xiaohongshu.py`。采集逻辑、默认检索词、CSV/断点处理和必要JS已经内置；**不是依赖旧项目的启动壳**。

三站统一采用 **Python → 本机 CDP 浏览器 RPC → 站点原生请求链路 → Python落盘**。抖音保留已验证的页面fetch链路，小红书保留原生客户端桥接，快手改为页面原生REST客户端；不另建RPC服务、不装浏览器插件、不复制Cookie或维护Node签名器。默认端口为抖音9222、小红书9223、快手9224。RPC不绕过登录/验证，也不保证更高安全频率。

正在运行的旧任务不会热更新；正常停止并重启后才切换新版。快手RPC通过125项离线回归及独立浏览器假页面检查。开发期间未与旧任务并发测试；用户随后自行启动新版，2026-09-29 18:45:51只读观察到9224 RPC已提交9页评论、无本轮错误。搜索全链路和长期稳定性尚未验收；记录见 `js_reverse_cache/rpc_live_observation.json`，历史HTTP测试不能替代RPC验收。

**总开关默认启用停止警报**（无需新依赖）：失败退出、启动失败、退出码2（仍待补/可能参数错误）及快手评论暂停都会提醒。Windows弹出置顶确认框并使用系统提示音（受系统设置影响）；弹窗不阻塞其它平台，总开关正常退出后仍可确认。窗口标题保留各平台状态，运行时每30秒重显未解除的警报。

不翻日志也可打开 **`logs/最新状态.txt`** 看平台状态、原因摘要、更新时间和日志路径；本轮 `状态.txt`、追加式 `警报.txt` 保留在运行目录。正常退出0和总开关Ctrl+C不报故障；确认弹窗只表示已看到，不控制重试；自动续采由倒计时安排，历史警报不删除。直接运行 `collectors/*.py` 不带这个监控，需要警报请用 `start_all.py --only 平台名`。

自动续采会显示倒计时和已重试次数；同轮重试追加原平台日志，不覆盖旧错误、不清断点、不重扫完成任务。明确登录/验证码、CSV占用或损坏、未知错误需人工处理；次数用尽后保留警报并停止。若响应提供有效 `Retry-After`，等待不得短于它；该字段无效时不自动重试。快手明确频控、HTTP429或未明 `result=2` 都保守冷却：默认15/30/60分钟（配置冷却的3倍，至少15分钟），但未明 `result=2` 不直接断言为频控。签名在等待结束后才生成；这不能保证平台一定解除限制。

**全量续采、失败全停（无参数双击 `.bat` 已是此模式）：** `start_all.bat --fail-fast --retries 0`。启动时强制对照原需求文档逐词验证三站134个基础词、938个含年份查询及贴文/评论的含首尾日期2021-07-24～2026-07-24；沿用正式CSV/断点，不重搜完成任务。任何平台退出码1/2或连续评论停滞，全部平台停止并报警；不开自动续采。只有频控/访问/网络请求类失败才为**下一次手动启动**提高 `runtime/collector_rate_overrides.json` 的最低间隔；登录、CSV占用、坏数据不能靠降频修复。抖音单篇评论列表缺失（包括 `total>0` 但 `comments=null`）会保留未完成并移到队尾，本轮继续其它作品；连续3篇新出现缺失仍熔断，不能当作全量覆盖。CSV快照内容未变则跳过替换；本地文件被占用时仅暂停本站CSV写入，最多等待约30分钟，每分钟复查，释放后原进程自动续采（不重发已提交页面）；不强关Excel/WPS等外部程序。长期占用或权限不足仍全停并保留原断点。强杀/断电无法保证报警或写入终态，结合进程和日志时间判断。

**有界 `.bat` 续采测试：** `start_all.bat --only douyin --retries 0 --test-requests 3`（平台名可换 `kuaishou` / `xiaohongshu`）。每次只启一个平台；最多3次真实业务请求，成功页会正常落盘，达到上限返回2并保留断点，不等于全量完成。2026-09-28已分别实测：快手3页评论提交、抖音2页提交且1篇内容暂不可用、小红书3页提交；无本轮明确频控。详见 `js_reverse_cache/bat_collection_test_20260928.json`。不要与已在运行的正式 `.bat` 并行。

**提速档候选频率（不是已验证的稳定上限）：** 抖音30–45秒/请求、快手60秒/请求，均每30次休息5分钟；小红书60–75秒/操作，每30次休息5分钟，三平台各自单并发。抖音/快手CLI间隔下限仍为10秒，但更快配置未经本轮测试。三站分别在低负载下完成3轮×3次只读请求（仅抖音/快手评论和小红书详情接口），均成功；不覆盖全链路及长期稳定性，详见 `js_reverse_cache/stability_trial_summary_20260928.json`。

新版总开关将已知冷却截止时间原子写入 `runtime/collector_cooldowns.json`，重启后先等未满的冷却，不立即请求；Ctrl+C不删除该记录，过期值自动忽略，记录损坏则拒绝启动，避免提前请求。旧进程未记录的历史冷却不会被自动补写；请人工遵守等待，不删除文件绕过冷却。快手运行中仅评论暂停不会被强制重启，整轮结束后才可安排补评论。

**人工登录后续采（仅非严格模式，例如交互终端运行 `python start_all.py`）**：明确登录/验证异常会进入“等待人工登录/验证”，该平台工作进程退出，其他平台照常采集。你在原专用浏览器处理完成后，回到总开关窗口按 **1=抖音、2=快手、3=小红书**（Windows无需回车；其他终端需回车），只恢复正在等待的平台，沿用原断点。没有确认就不重启，也不轮询业务接口；确认后仍需登录则再次等待。不要把普通警报弹窗的“确定”当成恢复按钮。

人工确认不占用、也不重置自动重试次数；`--retries 0` 仍可人工确认。提前按键、对运行中平台按键均不启动新任务。有效 `Retry-After` 未到期时需等完再按，无效时仍停止；另支持“等待人工解除CSV占用”：关闭Excel/WPS中占用的CSV后按对应数字恢复，启动时先恢复数据库导出，不强行覆盖占用文件。小红书明确落入访问受限页时至少等30分钟并人工确认正常页面，再按3；不保证重新登录能解决。CSV损坏/未知故障不因数字键绕过。无交互输入时保持原来的失败退出行为；Ctrl+C取消所有等待。三站均在对应专用浏览器完成登录即可；快手新版不再读取 `KS_COOKIE` 或 `cookie.txt`。这些人工确认功能仅适用于非 `--fail-fast` 普通模式，默认严格BAT仍是故障全停后重新运行。

可调整或关闭自动续采：

```bat
python start_all.py --retries 3 --retry-delay 300
python start_all.py --retries 0
```

`--retries` 是每个平台在本次总开关运行期间累计的额外启动次数，不会因重新启动进程而清零；`--retry-delay` 首次等待秒数，后续倍增。Ctrl+C同时取消等待和在采任务。仅因缺少评论令牌等导致的退出2不自动循环空跑。

## 旧贴文也补高赞评论

贴文去重与评论完成状态分开。启动先检查所有旧贴文ID：没有评论记录的自动登记，未完成的沿原评论游标补采；不会因为关键词已搜完或旧版只补过评论总数就跳过。旧候选已经入库而CSV未更新时，先恢复导出，不重新请求那些已提交页。

抖音明确返回 `status_code=0、comments=null、has_more=0、total=0` 时，按正常零评论末页处理。实测权限受限/已删除作品还会返回成功码、null评论、无下一页，但缺少total/cursor；对这一窄形状只跳过该篇本轮评论，保留原游标、已存评论和未完成状态，继续其它作品，不额外请求旧详情。连续3篇出现该形状仍停止并冷却检查，避免全站响应降级时持续请求。其它畸形响应、业务拒绝、登录/验证仍停止，不伪装为无评论。

旧评论按篇轮流采一页，默认持续轮转直到接口结束，不让第一篇的上千页评论长期挡住其它旧贴文。`--comment-pages` 仍是显式单篇本轮页数上限；轮转分片本身不是采集上限，不会将未完成篇标成完成。

快手上轮分页停滞的旧评论，新一轮也从原游标尝试；同一轮不反复重试失败页。仅连续三篇新出现停滞才触发熔断，已知停滞不重复计入；普通模式暂停本轮评论但继续搜索，严格BAT则全停。评论断点不推进、不标完成。登录/限流、接口拒绝或响应结构错误仍结束当前工作进程，再由总开关区分冷却续采与人工处理；失败响应不冒充完成。小红书缺少缓存令牌的旧ID会明确列入覆盖报告，待正常搜索重新发现有效令牌；不伪造、不清空搜索进度，也不谎报全部完成。

## 字段完整性与旧记录补采

正式CSV不保留整列无真实值的字段；部分缺失仍为空，真实0保留。`未提供`、`不适用`等旧占位值不再充当网站数据。公共字段名称/顺序仍统一，但各CSV可见列会随实际数据增减，读取时按列名，不依赖固定列数。

每份CSV配套 `output/reports/<文件名>_字段报告.json`：记录完整字段清单、暂未导出的全空列、每列非空/缺失条数。**省略全空列不等于已补齐**；以后采到真实值会自动恢复该列。没有记录的CSV仅保留表头。

普通增量不为补字段而再次请求旧详情；搜索响应自然带回旧ID时可直接合并已有响应，不增加请求。字段补采需显式执行，且不推进原搜索/评论断点：

```bat
python collectors/douyin.py --repair-fields 20
python collectors/kuaishou.py --repair-fields 20 --keyword "双减" --no-year-queries
python collectors/xiaohongshu.py --repair-fields 20
```

抖音/小红书的N是最多补取N条缺少采集时间、作者或核心互动数的旧记录详情（抖音还检查时长）；已有采集时间但其它核心字段空缺时也会被选中。可选IP/话题、图文的空视频链接不触发反复补采。快手的N是最多搜索N页，仅更新匹配到的既有ID。它们仍需有效登录，仍遵守原限速；一次运行不保证找回全部记录。小红书缺少候选令牌的笔记要通过正常搜索重新发现。补采时间取当前真实请求时间，不冒充旧数据最初采集时间。

本轮结果和接口限制见 [分析报告.md](分析报告.md)。原始CSV/状态库备份在 `output/backups/field_completeness_20260928_130918/`，不要拿备份覆盖已补齐的新数据。
