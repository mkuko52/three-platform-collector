# 双机分片（仅 Windows x64）

本文件夹的 `start_forward.bat` 和 `start_reverse.bat` 是**本机源码启动脚本**，都依赖上一级项目的 `start_all.bat` 和本机Python环境。新版三站均使用浏览器RPC，采集无需另外安装Node。异机运行请解压同目录新版 `reverse_collector_windows_x64_rpc.zip`，运行**解压后的** `reverse_collector/start_reverse.bat`，不要只拷贝本文件夹表面的 `.bat`。

- 原始全量进程仍按原顺序运行，不会因这些文件热更新。**不要在它运行时再开本机 `start_forward.bat`；要确保两机确实分片时，须先等待原任务正常停止，再用原状态目录启动本机前半片。**原进程如果已经跑过后半片，异机对历史已完成查询可能重复；分片只能保证之后的查询分配互不重叠，不追溯修改旧断点。
- 同一份原需求生成每站 938 个有序查询。本机 `start_forward.bat` 跑第 1–469 个；异机便携包 `start_reverse.bat` 从第 938 个倒序跑至第 470 个。三站各自保持顺序分页、日期过滤和原有低频间隔；重复出现的贴文/评论 ID 最后离线去重。不共享登录态或断点，不把 CSV 当作断点。

## 本机（保留旧数据）

在本机现有采集停妥之后运行 `start_forward.bat`。它沿用本机已有 `runtime/`、`output/csv/`，不会删除已完成的查询、已有视频及评论断点。不启第二套同机进程。仅当需要继续采前半片时运行；如果本机全量已经完成，不必再跑。

## 打包与异机

当前便携包：**`双机分片/reverse_collector_windows_x64_rpc.zip`**。本次修复版同步三站RPC源码、抖音随机间隔、三站每30次业务请求休息5分钟及下方四个加速入口；同时修复旧评论重复重试/重复熔断、抖音异常时游标被重置、未知RPC结果被接管、CSV占用恢复、严格模式提示和EXE弹窗入口。解压后复制完整 `reverse_collector/` 文件夹到另一台 Windows x64 电脑，不要只复制 `.bat`；本机构建目录为 `dist/rpc/reverse_collector/`。

在已安装Python依赖和PyInstaller的打包电脑执行 `python build_reverse_portable.py`，不自动安装依赖；构建目录已存在时拒绝覆盖，请先移走后重建。新ZIP完整写好后才替换旧ZIP。包中不含Cookie、浏览器档案、数据库、日志或历史CSV；`runtime/` 只含请求间隔配置，保留打包时已有的更慢降频值。

过期HTTP包 `reverse_collector_windows_x64.zip`、`reverse_collector_windows_x64_login.zip` 及旧 `dist/reverse_collector/` 已清理，不再维护。后续源码修改和本机重新打包不会自动更新另一台电脑，须手工部署。

异机需要 Windows 自带 Edge（或自行安装的 Chrome/Edge）、自己的网络/获准的代理出口、可手动登录的三个平台。浏览器不是随包附带的；没有可用浏览器、未登录或验证码未解决时**不能无依赖地自动采集**。

1. 将便携包放在独立且可写的目录；不要与本机的 `runtime/`、`output/` 混放或同时运行两个总开关。
2. 先运行包内 `prepare_logins.bat`，打开三个独立Edge CDP窗口：抖音9222、小红书9223、快手9224。仅导航主页，不主动发采集请求（网页会自动加载资源）；人工登录三站并保持窗口打开。确认三个浏览器使用已获准的网络/代理，此脚本不替换代理、不绕过验证。各自登录态只存在异机的 `runtime/平台名/browser/`；无需复制Cookie。
3. 三站登录妥当后运行包内 `start_reverse.bat`，使用随包 `reverse_collector.exe`，无须异机安装Python或Node。RPC直接复用浏览器会话；任何一站失败即全停并保留断点。人工处理后再次运行同一个脚本，不要关闭浏览器，不要用Excel占用正式CSV。
4. 离线检查：在便携目录运行 `reverse_collector.exe --fail-fast --retries 0 --shard reverse --check`；不打开浏览器/访问站点，不证明登录有效、线上接口可用或长期稳定。

## 便携包的五个档位

以下入口都在**解压后的包内**，均保持 `--shard reverse` 后半片、故障全停、不自动重试。一次只开一个，共用该包的登录态、CSV和断点。**表中仅为没有额外降频时的初始档位**；包会保留打包时已有的更慢记录。例如小红书记录为135秒时，所有档位实际都是135–150秒，不是表中的10–25秒。实际以包内配置和启动日志为准。

| 包内入口 | 抖音间隔 | 快手间隔 | 小红书间隔 |
|---|---:|---:|---:|
| `start_reverse.bat` | 45–60秒 | 90秒 | 90–105秒 |
| `采集速度版本/start_reverse_fast.bat` | 30–45秒 | 60秒 | 60–75秒 |
| `采集速度版本/start_reverse_high_speed.bat` | 20–35秒 | 40秒 | 60–75秒 |
| `采集速度版本/start_reverse_ultra_speed.bat` | 10–25秒 | 20秒 | 10–25秒 |
| `采集速度版本/start_reverse_ultimate_speed.bat` | 10–25秒 | 10秒 | 10–25秒 |

区间为随机间隔；三站各自每30次业务请求休息5分钟。更慢的自动降频记录优先，请求处理/写盘耗时另计。这些是配置值，不是网站已验证的安全频率。各BAT支持追加 `--check` 做离线检查。

## 更新另一台电脑已有的便携版

先在异机正常停止旧采集，确认程序和工作进程退出、关闭旧报警弹窗；不要靠更新包强杀任务。新包解压到临时目录，备份旧目录后，仅替换旧目录内的程序、`_internal/`、`collectors/`、BAT入口、说明及原需求文档。**原 `runtime/`、`output/`、`logs/` 全部保留，不用新包的初始配置覆盖原限速/冷却记录。** 不要在临时解压目录另开第二套采集。更新后在原目录运行原分片入口，续用原断点。

若新版提示“小红书RPC结果不确定，不接管”：先确保旧采集已停止，在原专用浏览器人工检查并刷新页面，再运行原入口。不清Cookie、不切换账号，不删除断点/冷却来绕过提示。连续3篇新出现评论异常仍会熔断；已知停滞的旧任务仍待补，每轮最多尝试一次，不当作已完成。

## 后续手工合并

两台电脑都停止采集之后，只从异机复制 `output/csv/` 下六个 CSV 到**独立目录**，不要直接覆盖本机正在使用的 CSV，不要复制 Cookie、浏览器档案或断点库。你自行按平台+内容 ID 去重贴文，按平台+内容 ID+评论 ID 去重评论；每篇联合评论按真实点赞数选前20条。遇到两边字段冲突、缺失值或评论尚未翻完，保留原件人工核对，不能猜测为0或已完成。**CSV 合并不等于断点合并；合并结果不能直接替换本机采集状态用于续采。**

两台电脑同时对同一个平台账号发请求，不能保证加速或不触发网站限制；遇验证/限流按原故障全停流程人工处理，不能提高单站请求频率或并发。
